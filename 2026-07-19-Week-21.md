### Incident Management and Escalation

The section on incident and ticket management provided a clearer understanding of how structured IT support environments operate.

A typical ticket moves through several stages:

1. A user submits a request or reports an issue.
2. The technician records the relevant user and device information.
3. The issue is categorized and prioritized.
4. Initial troubleshooting is performed.
5. The ticket is resolved or escalated.
6. The solution is documented.
7. The ticket is closed.

I also learned more about the differences between requests, incidents, and problems.

Requests are generally routine tasks such as password resets or software installations. Incidents are unexpected interruptions to a service, while problems are the underlying causes responsible for one or more incidents.

The module also explained the common support escalation structure, beginning with self-service resources and progressing through Help Desk technicians, experienced support staff, engineers, developers, and senior specialists.

### Operating Systems and File Systems

The final part of the module covered the operating systems and file systems commonly encountered by IT professionals.

The operating systems included:

* Microsoft Windows
* Apple macOS
* Linux
* UNIX
* ChromeOS
* Android
* iOS and iPadOS

I also reviewed several important file systems, including:

* NTFS
* ReFS
* FAT32
* exFAT
* ext4
* XFS
* APFS

Each file system has different advantages, limitations, security features, and compatibility considerations.

For example, NTFS provides permissions, encryption, journaling, and support for large volumes, while FAT32 offers broad compatibility but has a maximum file size of 4 GB. exFAT is commonly used for removable storage because it supports larger files while maintaining good cross-platform compatibility.

The module also highlighted the importance of checking hardware, software, driver, and network compatibility before installing or upgrading an operating system.

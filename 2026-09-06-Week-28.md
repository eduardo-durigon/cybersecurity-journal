One of the first concepts reinforced by this module was **least privilege**.

Users should only have the permissions they actually need to perform their work, and administrative privileges should be limited as much as possible.

Even administrators should use normal user accounts for everyday tasks and only elevate privileges when administrative access is required.

This reduces the potential damage if an account or application becomes compromised.

The same principle applies to services and software.

If a service, account, application, or feature is not required, disabling or removing it reduces the number of possible ways an attacker can interact with the system.

### Windows Endpoint Protection

A large part of the module focused on the security controls available directly within Windows.

**Microsoft Defender Antivirus** provides built-in malware protection and can identify threats using both known malware signatures and behavioral or heuristic analysis.

Signature-based detection compares files against known malware patterns, while heuristic and behavioral detection can identify suspicious activity that may not yet have a known signature.

This reinforced the importance of keeping antivirus definitions and the scanning engine updated.

A security product is only useful if it can recognize current threats.

**Windows Defender Firewall** provides another layer of protection by controlling network traffic.

Firewall rules can control inbound and outbound connections based on factors such as:

* Applications
* Ports
* Protocols
* Network addresses
* Network profiles

The default approach of blocking unsolicited inbound connections while allowing most outbound traffic provides a useful starting point, but more restrictive rules can be configured when necessary.

The important idea was again that different security controls protect against different threats.

Antivirus does not replace a firewall, and a firewall does not replace antivirus.

### Encryption – EFS and BitLocker

The module also covered protecting **data at rest**.

Windows provides two important encryption technologies:

* **Encrypting File System (EFS)** — file and folder-level encryption
* **BitLocker** — full-volume encryption

EFS allows individual files and folders to be encrypted.

BitLocker takes a broader approach by encrypting an entire drive.

BitLocker can also work with a **Trusted Platform Module (TPM)** to securely store cryptographic information used during the startup process.

One thing this section reinforced is that normal file permissions alone are not always enough.

Permissions depend on the operating system enforcing them.

If someone gains physical access to a drive and attempts to access it through another environment, encryption provides an additional layer of protection.

This is another example of defense in depth appearing throughout the security material.

Browser extensions were particularly interesting because something as simple as an add-on can potentially gain significant access to browsing activity and website data.

Extensions should therefore only be installed when necessary and should come from trusted sources.

The certificate material also connected back to previous security topics.

When connecting to a website using HTTPS, the browser validates the server's digital certificate and establishes an encrypted connection using TLS.

Certificate warnings should not simply be ignored because they can indicate problems such as an expired certificate, an untrusted issuer, or a hostname mismatch.

### Malware and Workstation Security

The second half of the module moved heavily into malware.

Some of the malware types and behaviors covered included:

* Viruses
* Boot sector viruses
* Trojans
* Worms
* Fileless malware
* Backdoors
* Adware
* Spyware
* Keyloggers
* Ransomware
* Cryptomining malware

One useful distinction was understanding that malware can be categorized not only by how it spreads, but also by **what it does after infection**.

A worm can spread automatically between systems.

A Trojan disguises itself as legitimate software.

A backdoor provides unauthorized access.

Spyware collects information.

A keylogger records keyboard input.

Ransomware attempts to make data unavailable.

Cryptomining malware steals computing resources.

Understanding the behavior helps identify both the possible symptoms and the appropriate response.

### Malware Symptoms and Troubleshooting

Malware does not always produce an obvious warning saying that a system has been infected.

Possible symptoms can include:

* Slow startup
* Poor system performance
* High resource utilization
* Application crashes
* System freezes
* Browser redirects
* Unexpected pop-ups
* Changed browser settings
* Unwanted extensions
* Missing or renamed files
* Changed permissions
* Unexpected network activity
* Disabled antivirus software
* Disabled firewall protection
* Problems with Windows Update
* Fake security warnings

One of the most important lessons from this section was that **a symptom is not the same thing as a diagnosis**.

A slow computer could be infected with malware, but it could also have a failing drive, insufficient memory, too many applications running, or another software problem.

Troubleshooting still requires verifying the symptoms and isolating the actual cause.

### Endpoint Monitoring

The module also introduced endpoint monitoring technologies such as:

* **EDR — Endpoint Detection and Response**
* **MDR — Managed Detection and Response**

Traditional antivirus remains important, but modern endpoint security can also involve continuously monitoring system activity for suspicious behavior.

EDR can collect endpoint information, identify unusual activity, assist with investigation, and support incident response.

MDR extends this idea by providing monitoring and response through a managed security service.

This section helped show how endpoint security can move beyond simply scanning files for known malware.

### Malware Removal

One of the most useful parts of the module was the structured process for responding to malware.

The general procedure I worked through was:

1. Investigate and verify malware symptoms.
2. Quarantine the infected system.
3. Disable System Restore in Windows.
4. Remediate the infected system.
5. Update anti-malware software.
6. Perform scans and removal.
7. Reimage or reinstall if necessary.
8. Schedule scans and run updates.
9. Re-enable System Restore and create a clean restore point.
10. Educate the end user.

The quarantine step is particularly important.

If a computer is infected, disconnecting it from the network can prevent the malware from:

* Spreading to other systems
* Communicating with command-and-control infrastructure
* Downloading additional malware
* Continuing to exfiltrate information

If an infection is severe enough that the integrity of the operating system can no longer be trusted, attempting to manually remove every malicious component may not be the safest option.

At that point, **reimaging or reinstalling the operating system** can provide greater confidence that the machine is actually clean.

## Key Takeaways

The biggest theme for me this week was **endpoint security as a process rather than a single product or setting**.

There is no one switch that makes a workstation secure.

Account policies reduce unauthorized access.

Least privilege limits what users and compromised applications can do.

Execution controls restrict what software can run.

Antivirus detects malicious software.

Firewalls control network communication.

Encryption protects stored data.

Browser security reduces exposure to internet-based threats.

Endpoint monitoring helps detect suspicious behavior.

Backups and recovery procedures provide a way forward when prevention fails.

The malware section also reinforced the importance of approaching security problems through the same troubleshooting mindset used elsewhere in IT.

A technician should not see a slow computer and immediately decide that it has malware.

The symptoms need to be investigated and verified.

If malware is identified, the response then needs to follow a structured process.

The sequence I want to remember is:

**Investigate → Quarantine → Disable System Restore → Remediate → Update and Scan → Reimage if necessary → Re-enable System Restore → Educate the user**

I also found the encryption material particularly useful.

EFS and BitLocker solve different problems, but both reinforce the idea that protecting access to a computer is not necessarily the same as protecting the data stored on it.

Overall, Module 19 continued the pattern I have been noticing throughout Core 2.

The subjects are becoming increasingly interconnected.

Windows administration connects to account security.

Networking connects to firewall configuration and malware communication.

Browsers connect to certificates, encryption, privacy, and malware.

Troubleshooting connects to incident response.

The individual exam objectives increasingly feel like different parts of the same environment rather than separate topics to memorize.
